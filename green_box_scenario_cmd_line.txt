Green-box 시나리오 실행 명령 (final.xml + green_box_approach)
=============================================================

시나리오
  Nav2 목표(target)와 원점(0,0)을 계속 왕복한다(final.xml).
  주행 중 초록 박스가 확정 검출되면 다음 순서로 동작한다.
    박스 앞 0.8 m로 이동 → 박스 중심 0.55 m까지 천천히 접근해 정지
    → Place → Push 자세 → Pick → 최대 10초 대기 → 원래 경로로 복귀

터미널 구성 (각 터미널에서 먼저 0번 환경 설정)
  T1 Isaac Sim  |  T2 MoveIt move_group  |  T3 MoveIt↔Isaac bridge
  T4 Nav2       |  T5 green_box detector |  T6 RViz
  T7 목표 전송 / 모니터링


0. 환경 설정 (모든 ROS 터미널)
------------------------------
source /opt/ros/humble/setup.bash
source /home/ciderlab-server3/workspace/2026_industry_cowork/IsaacSim-ros_workspaces/humble_ws/install/setup.bash
# ROS_DOMAIN_ID 등은 기존에 쓰던 설정을 그대로 사용한다 (Isaac의 ROS2 bridge와 같아야 함).


1. Build (코드나 패키지가 바뀌었을 때만)
----------------------------------------
cd /home/ciderlab-server3/workspace/2026_industry_cowork/IsaacSim-ros_workspaces/humble_ws
colcon build --packages-select custom_nav2_bt_plugins green_box_approach
source install/setup.bash
# BT XML(final.xml)과 params yaml은 절대경로로 읽으므로, 수정만 했다면 재빌드는 필요 없다.


2. Isaac Sim (T1)
-----------------
~/isaac-sim-standalone-5.1.0-linux-x86_64/isaac-sim.streaming.sh
# WebRTC Streaming Client로 접속한 뒤 초록 박스가 있는 stage를 열고 Play한다.
# 맵은 1_obs.yaml을 쓰므로, stage도 1_obs 계열(초록 박스 배치)이어야 한다.


3. MoveIt move_group (T2)
-------------------------
ros2 launch turtlebot3_manipulation_moveit_config move_group.launch.py
# Place / Push / Pick 노드가 /arm_controller/follow_joint_trajectory,
# /gripper_controller/gripper_cmd 액션을 사용한다.


4. MoveIt → Isaac bridge (T3)
-----------------------------
cd /home/ciderlab-server3/workspace/2026_industry_cowork/IsaacSim-ros_workspaces/humble_ws/src
python3 moveit_to_isaac_bridge.py --ros-args \
  -p use_sim_time:=true \
  -p relay_joint_states:=false \
  -p isaac_state_topic:=/joint_states \
  -p isaac_command_topic:=/joint_commands


5. Nav2 (T4)
------------
ros2 launch nav2_bringup bringup_launch.py \
  use_sim_time:=true \
  map:=/home/ciderlab-server3/workspace/2026_industry_cowork/IsaacSim-ros_workspaces/humble_ws/src/L_corridor.yaml \
  params_file:=/home/ciderlab-server3/workspace/2026_industry_cowork/IsaacSim-ros_workspaces/humble_ws/src/L_corridor_nav2.yaml
# final_nav2_params.yaml이 final.xml을 기본 BT로 쓰고, green-box 플러그인 3개를 로드한다.
# 초기 위치는 params에서 (0,0,0)으로 자동 설정된다(set_initial_pose: true).
# 로그에 "custom_is_green_box_detected_condition_bt_node" 등의 로드 에러가 없어야 한다.


6. green_box detector (T5)
--------------------------
# (1) 먼저 카메라 토픽 이름을 확인한다. 이 값은 레포에서 확정할 수 없었다.
ros2 topic list | grep -iE "image|camera|rgb"
#     기존 메모에서 쓰던 카메라 정보 토픽: /front_camera_info (depth: /depth_camera)

# (2) optical 프레임 TF가 있는지 확인한다 (없으면 camera_frame 값을 실제 optical 프레임으로 바꾼다).
ros2 run tf2_ros tf2_echo base_link camera_optical

# (3) detector 실행. <RGB_TOPIC>, <CAMERA_INFO_TOPIC>은 (1)에서 확인한 값으로 바꾼다.
ros2 run green_box_approach detector_node --ros-args \
  -r __node:=green_box_detector \
  -p use_sim_time:=true \
  -p camera_frame:=camera_optical \
  -p output_frame:=map \
  -p scan_topic:=/scan \
  -p image_topic:=<RGB_TOPIC> \
  -p camera_info_topic:=<CAMERA_INFO_TOPIC>
# launch 파일(green_box_approach.launch.py) 대신 ros2 run을 쓰는 이유:
#   launch 파일은 use_sim_time을 설정하지 않는다. 그러면 detector만 wall clock을 써서
#   green_box/pose의 타임스탬프가 Nav2(sim time)와 어긋나고, IsGreenBoxDetected의
#   max_age(1초) 판정이 항상 실패할 수 있다.
# output_frame은 final.xml의 global_frame="map"과 같아야 한다.


7. RViz (T6)
------------
ros2 launch nav2_bringup rviz_launch.py use_sim_time:=true
# 튜닝용 디버그 영상 (HSV 마스크, bbox, 판정 사유):
ros2 run rqt_image_view rqt_image_view /green_box/debug_image


8. 목표 전송 (T7)
-----------------
# RViz의 "Nav2 Goal"로 찍거나 아래 명령을 쓴다. 이 목표가 왕복의 target이 된다.
# final.xml은 무한 왕복이라 액션이 끝나지 않는 것이 정상이다 (Ctrl+C로 취소).
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: map}, pose: {position: {x: <X>, y: <Y>}, orientation: {w: 1.0}}}}"


9. 모니터링 / 테스트 (T7 등)
----------------------------
# 검출 여부 (확정되면 true)
ros2 topic echo /green_box/detected
# 박스 중심 좌표 (map)
ros2 topic echo /green_box/pose

# 대기 단계를 10초 전에 해제하는 테스트 (나중에 로봇팔 쪽에서 보낼 이벤트와 같은 형식)
ros2 topic pub --once /obstacle/still_present std_msgs/msg/Bool '{data: false}'


참고
----
- 거리 값 (final.xml, 두 leg 모두): standoff_distance 0.8, stop_center_distance 0.55,
  stop_distance 0.4. 모두 0.3 m 박스 기준 임시값이다.
- detector의 box_depth_m / box_height_m (기본 0.30)도 임시값이다. 필요하면 6번 명령에
  -p box_depth_m:=... 을 추가한다.
- 박스가 계속 안 잡히면 debug_image의 reason 텍스트(narrow / no-range / clipped / confirming)를 확인한다.
- 예전 perception 노드(rgbd_obstacle_localizer, perception_stabilizer)는 이 시나리오에서 실행하지 않는다.
